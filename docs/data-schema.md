# Property Hunt persisted data schema

This document is the contract between the deterministic collector and downstream analysis agents.

## Run summary

`reports/latest.json`

Authoritative summary of the most recent collector run.

Important keys:
- `run_id`: UTC timestamp for the collector run.
- `counts.collected_listings`: fresh listings collected in this run.
- `counts.state_listings`: effective listing state after safe snapshot preservation.
- `counts.transactions`: fresh sales transactions collected in this run.
- `counts.state_transactions`: effective transaction state.
- `counts.rents`: registered/live rental evidence collected in this run.
- `counts.projects`: project/construction records.
- `counts.auctions`: auction/distress records.
- `counts.market_metrics`: secondary aggregate market metrics.
- `counts.registry_entities`: unit/building/land/developer registry records.
- `diagnostics[]`: per-source status. `ok` means usable evidence was parsed. `partial` means incomplete. `query-gated` means the official source was reachable but rows require an interactive query or credentials. `unsupported` must not be treated as evidence.
- `snapshot.listing_snapshot_preserved`: current listing collection was incomplete, so prior listing state was retained.
- `snapshot.transaction_snapshot_preserved`: fresh transaction evidence was unavailable, so prior transaction state was retained.
- `candidates[]`: deterministic shortlist generated by the pipeline.

`reports/latest.md` is the human-readable rendering of the same run.

## Persisted state

### `data/state/listings.parquet`
Model: `property_hunt.models.Listing`

Key fields: source/source_id, URL, ask price, area, bedrooms/bathrooms, building/community, property type/status/furnished, canonical building ID, layout group, duplicate group, conflicts/warnings, provenance.

### `data/state/first_seen.parquet`
Immutable first-observed copy of each listing. Use with current listings and observations to identify stale/reduced/relisted inventory.

### `data/state/observations.parquet`
Model: `Observation`.
Historical listing observations containing listing ID, observation time, price, area, status and provenance.

### `data/state/events.parquet`
Model: `ListingEvent`.
Added/changed/removed listing events. Removal events are suppressed when current listing collection is partial.

### `data/state/transactions.parquet`
Model: `Transaction`.
Registered sales evidence. Key fields: building/community, date, consideration, area, bedrooms/property type, canonical building ID and provenance. Prefer official DLD evidence where available; authenticated DXBinteract building/area transaction evidence may supplement it.

### `data/state/rents.parquet`
Model: `RentalRecord`.
Rental evidence. Key fields: building/community, annual rent, area, bedrooms, contract date, property type, `registered`, provenance.

### `data/state/projects.parquet`
Model: `Project`.
Project/construction evidence. Key fields: project name, developer, community, status, start/end dates, completion %, inspection/completion dates, total units and provenance.

### `data/state/auctions.parquet`
Model: `AuctionRecord`.
Auction/distress evidence. Key fields: title, URL, location, property type, auction date, current bid, reserve/start-price estimate, area, bedrooms, status and provenance.

### `data/state/market_metrics.parquet`
Model: `MarketMetric`.
Secondary aggregate market evidence. Includes source, period, geography/segment, transaction count/value, median sale/rent PSF and provenance. Never substitute these aggregates for available same-layout/same-building transactions.

### `data/state/registry.parquet`
Model: `RegistryEntity`.
Official registry metadata for unit/building/land/developer-type entities. Includes entity type/name, parent/project/community, floor/room type/size/parking and provenance where available.

## Source hierarchy

For Dubai investment underwriting use:
1. DLD official transaction/project/unit/building/rent/service-charge data.
2. Other official Dubai government data.
3. Authenticated/public DXBinteract transaction/rent/project evidence.
4. Property portals for live asking inventory and listing attributes.
5. Emirates Auction for auction/distress evidence.
6. Broker/social commentary only as low-confidence supplementary context.

## Source-state rules

- Never treat a `query-gated`, `partial`, or `unsupported` diagnostic as fresh records.
- Never infer that zero fresh records means zero market activity when a source is partial/query-gated.
- If a listing source is partial and `listing_snapshot_preserved=true`, use the retained state only as historical/current-best-known evidence and explicitly disclose its age.
- If transaction evidence is stale or unavailable, do not calculate a precise valuation premium/discount from aggregate market metrics alone.
- Every externally verified fact added by an analysis agent must be distinguishable from deterministic persisted evidence.

## Underwriting rule

The deterministic candidate model is a screening layer, not final investment advice. Final analysis must verify material comparables, rents, service charges, occupancy/condition, project progress and competing inventory before issuing a buy/fair/reject judgment.
